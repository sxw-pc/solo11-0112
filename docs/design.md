# 业务模型与边界

历史账本的旧值重演、新规则差异、依赖重算与乐观写入共同决定补偿是否安全；失败时目标事务回滚。

## 实体关系

Batch 关联多个 Subject 与 SourceFile；SourceFile 的原始字节和 SHA-256 不覆盖，RawEvent 引用来源行；RuleVersion 被 Evidence 引用；一次 Run 关联多个 Decision、Evidence、Issue。非法输入留下 Issue，不写出无依据的成功结论。

## 状态和失败

导入与身份校验结束后 Run 进入已校验；有无法判定主体时进入待核，否则已判定。规则版本变化产生新 Run，旧 Decision 保留。源哈希冲突、身份冲突、依赖环、证据缺口和执行失败各有独立错误或问题码。写操作只允许显式沙箱，原始来源保持只读。

## 首版以外的自然扩展

多数据库补偿、流批并行水位、分区灰度、检查点续做、成本限流、多版本迁移、缓存失效通知、审批签章。以上均未实现。

## 跨库中断恢复

目标库与控制库是两个独立 SQLite 文件，无法共享事务：目标侧 ledger 与 backfill_audit 先提交，控制侧 execution 与租约释放后提交。恢复裁定把两侧在同一时刻的状态冻结为 repair_case/repair_row，证据哈希排除时间戳以保证同现场重复取证一致。硬阻断（第三方改写、审计矛盾、无审计新值、计划变更、部分 execution、租约异主、目标缺失、已发布消费者）不允许任何自动恢复；可恢复现场只接受维护者显式选择前进或回退，且决定时刻重新取证而非信任冻结快照。前进只补记控制事实，回退在目标库单事务内逆序改账并把审计置为 rolled_back；两条路线都消费或释放同一租约、阻止其他计划抢占。回退路线在目标提交后再中断时按行审计重入，重复命令收敛到同一最终状态。
