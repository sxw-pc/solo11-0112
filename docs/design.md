# 业务模型与边界

历史账本的旧值重演、新规则差异、依赖重算与乐观写入共同决定补偿是否安全；失败时目标事务回滚。

## 实体关系

Batch 关联多个 Subject 与 SourceFile；SourceFile 的原始字节和 SHA-256 不覆盖，RawEvent 引用来源行；RuleVersion 被 Evidence 引用；一次 Run 关联多个 Decision、Evidence、Issue。非法输入留下 Issue，不写出无依据的成功结论。

## 状态和失败

导入与身份校验结束后 Run 进入已校验；有无法判定主体时进入待核，否则已判定。规则版本变化产生新 Run，旧 Decision 保留。源哈希冲突、身份冲突、依赖环、证据缺口和执行失败各有独立错误或问题码。写操作只允许显式沙箱，原始来源保持只读。

## 首版以外的自然扩展

多数据库补偿、流批并行水位、分区灰度、检查点续做、成本限流、多版本迁移、缓存失效通知、审批签章。以上均未实现。

## 历史翻转的因果诊断

`causality_pair` 冻结两次真实 run 的主体决策、证据事件 ID/payload/digest、来源原始字节摘要，以及配置与账本快照的身份摘要。可比性闸门先证明两个 run 同批次、同配置身份、同账本快照，且比较 run 的证据事件集合恰为基线事件加上若干保有原始字节的新来源；旧来源变异、基线事件消失、配置/快照漂移、来源摘要不符或任一 run 未通过 `report.verify` 时结论只能是 `unsupported`。同 event_key 异文等无法归属的 identity_conflict、解析失败或原始字节缺失保留为 `indeterminate`，不把失败解释成正常“待核”。

干预单元是整个来源文件：同文件多条事件一并纳入或排除。每个反事实都从原始基线输入在临时控制库中按确定顺序真实执行 `ingest.load`→`rules.evaluate`，生产控制库不删 raw_event、不改历史证据；证书只记录确定性事实（子集掩码、来源摘要、全部主体状态、父依赖影响链、解析问题），临时库路径不进入摘要，因此同字节跨进程重放幂等。新增来源单元 ≤12、主体 ≤12、依赖边 ≤30 时完整枚举 2^n 子集并声明搜索完整；越界或搜索未完成只能 `indeterminate`，禁止伪完整归责。

`necessary_change` 回答“哪项变化是单独必要原因”（撤去单项即回到基线；无则显式 none），`minimal_sufficient_change` 回答“有哪些独立充分的最小变化组合”（枚举全部包含极小子集，不止第一个）。两合同共享同一事实库，诊断不改写任何来源；`causality-verify` 从冻结字节与沙箱重放独立复算全部反事实与结论，命名漏报充分原因、错选子集、伪造来源、历史 run 篡改与上游传播遗漏。
