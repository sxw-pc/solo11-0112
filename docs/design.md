# 业务模型与边界

历史账本的旧值重演、新规则差异、依赖重算与乐观写入共同决定补偿是否安全；失败时目标事务回滚。

## 实体关系

Batch 关联多个 Subject 与 SourceFile；SourceFile 的原始字节和 SHA-256 不覆盖，RawEvent 引用来源行；RuleVersion 被 Evidence 引用；一次 Run 关联多个 Decision、Evidence、Issue。非法输入留下 Issue，不写出无依据的成功结论。

## 状态和失败

导入与身份校验结束后 Run 进入已校验；有无法判定主体时进入待核，否则已判定。规则版本变化产生新 Run，旧 Decision 保留。源哈希冲突、身份冲突、依赖环、证据缺口和执行失败各有独立错误或问题码。写操作只允许显式沙箱，原始来源保持只读。

## 多消费方发布协定

单个消费方的 gate 只说明“该方在当时目标上可发布”，无法表达共享同一回填计划的多个消费方之间的共同封存版本。发布协定因此独立于 gate：协定记录成员、每方授权主体范围、expected 摘要、共享计划摘要、目标快照、route 与版本。准备时冻结成员和快照；提交前重新读取运行、计划摘要与目标哈希，任一漂移使未发布协定 `stale`，已发布协定只记录观测而不改写。

两种合法路线在准备前固定：`atomic` 以整个协定为发布单位，任一成员非 ready 则谁都不能发布；`partitioned` 以“无共享主体且无依赖边”的连通分量为发布单位，重叠范围与依赖成员同组，避免同一消费方看到混合版本。共享主体上不同成员给出不同 expected 值属于身份冲突，准备阶段即拒绝并留下拒绝记录。历史版本按 `accord_id:version` 分别保存，成员与快照由触发器禁止更新与删除。

## 首版以外的自然扩展

多数据库补偿、流批并行水位、分区灰度、检查点续做、成本限流、多版本迁移、缓存失效通知、审批签章。以上均未实现。
